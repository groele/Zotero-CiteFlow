# Zotero 10.0.6 / Word drag citation investigation

The supplied 40.0.3 add-on fails a real Word insertion on this machine before it can create a citation field. Its `citeItems` passes a null document name to `Zotero.Integration.execCommand("WinWord", "addEditCitation", null, 1)`. The installed Zotero 10.0.6 WinWord adapter implements `getActiveDocument()` through `getDocument(null)`, then calls `documentName.indexOf()` without a null check. An isolated run returned `TypeError: can't access property "indexOf", documentName is null` from `zoteroWinWordIntegration.mjs:243`.

A diagnostic build of the unchanged 40.0.3 insertion code, with only the active-document empty-name adapter used in CiteFlow, inserted a real `ADDIN ZOTERO_ITEM CSL_CITATION` field into Word. The result was `(Author0, 2024)`. CiteFlow 10.0.0 already carries this adapter in `src/modules/cite.mjs`, so rebasing on 40.0.3 without it would reintroduce the failure.

The original drag wrapper also reads Zotero's selection before calling the native `onDragStart`. The native handler selects the row under the pointer first. CiteFlow now follows that order so directly dragging an unselected row captures the dragged item. The regression test covers this case; 33 repository tests and 38 isolated Zotero settings checks passed. The 10.0.0 version was unchanged.

Two human Zotero-to-Word drags in the isolated legacy comparison did reach Zotero's real `dragend` handler at screen positions `(1170, 358)` and `(1221, 380)`, outside the Zotero window. Both had `dataTransfer.types=["text/plain"]`, `mozUserCancelled=false`, and `dropEffect="none"`; neither called `citeItems`, and the Word field count stayed at one (the prior API probe). The empty payload used to suppress native bibliography text is rejected by Word, so `dropEffect` is not a reliable success signal for this integration.

CiteFlow now accepts an external, non-cancelled drag even when `dropEffect="none"`. It still ignores drags ending within Zotero and explicitly cancelled drags. The drag lifecycle regression tests cover these cases. The final 10.0.0 candidate passed 33 repository tests and 38 isolated native settings checks.

The physical cross-window acceptance was completed with that candidate in the isolated Zotero 10.0.6 profile. The trusted `dragstart` at `(439,274)` selected item 5. The trusted `dragend` at `(1383,336)` had `types=["text/plain"]`, `dropEffect="none"`, and `mozUserCancelled=false`; the trace records `cite-call` for item 5 and `cite-complete`. The Word document uses a note citation style, so its main-story `Fields.Count` is zero by design. Its two footnotes each contain one native `ADDIN ZOTERO_ITEM CSL_CITATION` field, with results for Author0 and Author1. A native Zotero refresh completed successfully and preserved both fields. This is a real user-performed Zotero-to-Word drag, not a synthetic event or API-only insertion.
