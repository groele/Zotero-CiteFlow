# Zotero CiteFlow v13.0.5 阶段说明（拖拽释放二次防呆校验、回收站文献序号隔离与 Win32 原生句柄复用）

## 1. 核心目标

围绕用户提出的**“提升稳定性、优化性能、增强鲁棒性，绝不允许因参考文献引用错误引发学术不端风险，全面保障架构稳定、代码稳定、机构设计稳定”**要求，对全量 27 个源码模块进行了系统性梳理，重点攻克了**“Word 历史引文残留已删除文献挤压正常引文序号”**、**“拖拽释放时刻条目状态二次核验”**以及**“Win32 原生句柄高频开关开销”**三大核心环节。

## 2. 四大核心工程加固

1. **文内引文序数计算的回收站文献硬隔离（`order-cache.mjs` / `formatting.mjs`）**
   - **风险场景**：当用户在论文写作中发现某篇已插入 Word 的文献存在问题并将其移入 Zotero 回收站（Trash），在 Word 尚未手动删除该引文域前，`citationsByIndex` 仍会返回该文献 ID。若不加过滤，该废弃文献仍会占据序号 `1`，导致后续所有正常文献的显示序号整体顺延错位。
   - **加固设计**：在 `getSortedItemIDs` 与 `_applyCitations` 中核验 `Zotero.Items.get(id)`，一旦发现 `deleted === true || inTrash === true`，立即将其从有效引文序数计算和 `idData` 映射中剔除，确保正常文献序号与标签统计绝对纯粹、准确。

2. **拖拽释放时刻（`dragend`）二次合法性防呆校验（`src/modules/views/drag-cite.mjs`）**
   - 在 `onDragStart` 捕获选中条目后、到 `dragend` 实际调用 `addon.api.citeItems` 之间，新增二次完整性过滤（校验 `deleted !== true`、`inTrash !== true`、`isRegularItem()`、`isTopLevelItem()` 及正安全整数 ID），同時保持 `src/modules/cite.mjs` 与原生 Zotero 10 引文引擎 SHA-256 签名 100% 字节级一致。

3. **视图层 `currentSession` 存在性校验加固（`src/modules/views/session-index.mjs`）**
   - 在 `getCitationText` 中校验 `currentSessionID && index.sessions[currentSessionID]`，防止当 `Zotero.Integration.currentSession` 指向尚未注册或非 Word 会话时阻断唯一匹配回退。

4. **Win32 原生 `ctypes` 句柄缓存与生命周期闭环（`drop-target.mjs` / `hooks.mjs`）**
   - 将 `user32.dll`、`kernel32.dll` 动态库句柄、Win32 API 声明及 `32768` 宽字符路径缓冲区升级为懒加载单例缓存（`getDropTargetCtypes`），使每次拖拽目标识别达到零 DLL 重复加载开销；
   - 在 `hooks.mjs` 的 `onShutdown` 中新增 `closeDropTargetCtypes()` 停机清理步骤，确保插件禁用或卸载时 100% 释放原生句柄。
