# Zotero CiteFlow v13.0.3 阶段说明（学术引文零差错决定性、稳定性、鲁棒性与性能深度加固）

## 1. 核心目标

围绕学术写作中最核心的**“参考文献引用零差错、绝不因软件状态异常导致错引/漏引/乱序”**原则，在 `v13.0.2` 完成 27 模块物理架构解耦的基础上，对引文序数排序算法、Word 异步快照一致性、回收站文献防误引、后台轮询并发安全及高频 UI 渲染性能进行了全方位商业级加固。

## 2. 六大关键加固与优化

1. **学术引文序数排序决定性加固（`src/modules/citation/order-cache.mjs`）**
   - 新增 `_isValidCitationIndexKey(key)` 与 `_parseValidItemID(rawId)`：严格校验 `citationsByIndex` 索引键必须为非负安全整数、文献 ID 必须为正安全整数。
   - 彻底消除当宿主对象混入非数字属性键时 `Number(a) - Number(b)` 返回 `NaN` 导致 JavaScript `Array.prototype.sort` 比较器失效、引文序号 `[1], [2], [3]` 发生静默错位的隐患。

2. **Word 集成双向撕裂快照保护（`src/modules/citation/formatting.mjs`）**
   - 在 `_readSessionCitationSnapshots` 中升级双向撕裂检测（`hasTornSnapshot`）：当 `citationsByIndex` 与 `citationsByItemID` 任一方非空而另一方因 Word 域正在刷新暂时为空时，自动等待 `50ms` 重试 `updateFromDocument(0)`；若仍未就绪则返回 `transientMismatch: true`，完整保留上一次已验证的正确引文状态与标签，绝不因瞬态半成品快照误删引用记录。

3. **回收站与已删除文献全链路硬拦截（`tag-governance.mjs` / `formatting.mjs` / `drag-cite.mjs`）**
   - 严格对齐 `AGENTS.md` 第 5.4 节要求：显式校验 `item.deleted === true || item.inTrash === true`。
   - 拦截回收站或已删除条目进入拖拽引文（`_onDragStart`）、拦截其加入文档引文临时集合（`_applyCitations`）、拦截对其执行标签写入（`_isWritableCitationItem`），从源头杜绝引用已废弃/撤回/删除文献的学术风险。

4. **拖拽引文幂等去重与过期熔断（`src/modules/views/drag-cite.mjs`）**
   - 在 `_onDragStart` 中按 `item.id` 对选中条目集合执行确定性去重，防止同一批次拖放产生重复引文；
   - 增加 `60,000ms` 拖拽状态有效期校验，避免跨窗口异常中断后残留陈旧拖拽上下文。

5. **后台轮询防重入互斥锁（`src/modules/citation/word-integration.mjs`）**
   - 在 `listener(t)` 中引入 `_isTickRunning` 异步互斥锁，确保当 Zotero 数据库繁忙或大文档刷新耗时较长时，后续定时器 Tick 不会并发重入造成竞态覆盖。

6. **有界缓存与虚拟树 $O(1)$ 渲染优化（`order-cache.mjs` / `icon-patch.mjs`）**
   - `_sortedCacheBySession` 增加 64 会话上限 FIFO 淘汰策略；
   - `_rememberIconNode` 仅在缓存节点数达到阈值时执行断连 DOM 清扫，将虚拟列表每行渲染复杂度降至 $O(1)$。
